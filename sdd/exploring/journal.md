2026-09-05 P-001 探索内容

### 背景与约束

- I-001 拆出：加速核心 = 改写内置市场 GitHub 请求地址为镜像地址
- 用户约束：不发布社区插件库、不考虑移动端
- 已知事实：内置市场完全建立在 GitHub 之上——列表 JSON 来自 obsidianmd/obsidian-releases，插件安装下载 release 资产，主题下载仓库快照 zip，更新检查读各仓库 manifest

### 候选方向（加速作用面）

- 选项一 · 加速内置社区插件流程：无官方拦截点，需补丁式改写；桌面端或可尝试；移动端不可行；存在审核合规风险
- 选项二 · 本插件自带界面：BRAT 先例证明插件间安装可行（写 .obsidian/plugins/ 后重载），全部走受支持能力面，双端一致；代价是与内置市场功能重叠
- 选项三 · 两者结合：自带界面为主线，内置拦截另立提案先 spike
- 演进：初判倾向选项二 → 用户裁定选项一（不考虑发布与移动端，两大障碍移除）→ 选项一升为主线，选项二降为回退方案

### Spike 历程（V1-V6，逐步详情见上方 6 行日记）

- V1 请求画像 / V2 renderer 层未命中 / V3a 判定主进程 / V3b IPC 命中（request-url 频道、URL 明文、载荷含 status）/ V4 部分通过（raw 通、release 404）→ 换镜像复测 → V4 通过（完整安装链路）
- 实测沉淀：默认镜像 gh-proxy.com；ghproxy.net 实装 404；ghfast.top/moeyy 不可用；四公共镜像仅两个覆盖 release 资产

### 决策

- 路线图收编：M2-M4（自带界面相关）删除，产品 = 内置市场加速器
- 边界：镜像源可配置 + 总开关；失败原样呈现不做自动回退；404 语义按路径二分（releases 覆盖缺失计失败，raw 真值不计）
- 播种与观测交互：开关 off 期间添加镜像，自动首测照常执行（诊断动作与开关无关）

### 否决

- 自带市场界面（A-001）
- 镜像元数据源（A-002）
- ghproxy.net 作为默认镜像（实装 404，实测数据否决）

### 方法学教训

- 外层探针记录的是改写前快照；函数名 grep 无法验证压缩构建；console.debug 默认被 Verbose 过滤隐藏；测试场景必须保证状态可外部观测

2026-09-05 P-002 探索内容

### 背景与约束

- 承接 P-001：单镜像引擎 + base 身份键控游标已就绪；MirrorCandidate 的 type 判别字段已预留
- 用户拍板：纯用户池（内置目录降级为默认种子）、轻量测试按钮（requestUrl）、类型集 = prefix + 域名替换

### 探索决策

- 统一映射模型：prefix 本身即映射（to = base + from，与现有实现逐字节等价）；组合型镜像天然可描述；无存量数据非破坏性——type 两分模型被替代，新服务接入从写代码降级为提供映射数据
- 行为边界三分类：命中映射加速 / GitHub 已知域未覆盖直连并按 host 聚合提示 / 非 GitHub 静默直连
- 录入与验证语义：github 与 raw 两映射必填；添加即入池（不因测试回退）+ 入池后自动首测；GET 小资源不用 HEAD/OPTIONS；失败标记不自动删除
- 重复判定与镜像身份：镜像名即唯一标识，同名即重复；映射内容派生身份方案否决
- 池条目 UI：collapsed 条目（名 + 检测结果 + 菜单）/ 点击展开详情只读 / 映射编辑预留未来提案
- 空池不可达：最后镜像不可删（开关开 ⇒ 池非空 ⇒ 必在加速）
- 生命周期分层：池持久化（仅用户池管理操作与播种改变）；运行态会话内存（插件重载即清空）
- 全池首测触发 = 池建立/重建（播种、恢复初始状态）；池沿用场景不触发
- 手动切换下一镜像：复用推进语义，补「慢而不败」盲区
- 复位按钮 + 拉黑 30 分钟冷却（解除时清零连败）；开关复位否决（副作用）

### 否决

- 直连兜底（链尾哨兵）——静默降级，手动开关已覆盖
- 开关复位——复位是开关职责外的副作用
- 映射内容派生身份——为边缘认知负担加内部复杂性

### 方法学教训

- 测试场景构造须与实现语义逐笔对账（本轮 8 处断言/场景笔误均经显式账本核对修正，实现语义全程未变）

2026-09-05 P-003 探索内容（原 exploring/P-003.md）

### 已知信息与约束

- P-002 已交付：被动健康观测、失败推进 + 3 败拉黑 + 30 分钟冷却的自动切换、base 身份键控游标（池重排/增删不张冠李戴，本提案的直接基础）
- MirrorCandidate 的 type 判别字段与 rewriteUrl 分发骨架已预留（当时仅 prefix 一个分支）
- 用户已拍板：纯用户池模型（内置目录降级为首次默认种子）、轻量「测试此镜像」按钮（requestUrl 单点主动探测）、支持前缀拼接与域名替换两类
- 不做：目录远程热更新、批量主动健康探测
- 种子集合为实现期决策：实现任务内实测筛选、确保入选全部可用；探索期 4 项仅为候选参考（gh-proxy.com 实测验证可用，ghproxy.net 曾 404，ghfast.top/moeyy 未验证可用）

### 候选方案

- 方向 A · 纯用户池 + 默认播种（保守，用户已选）：设置持久化有序镜像池，首装/存量数据播种内置目录，池全权归用户；缺：内置目录随版本更新不再自动触达已播种用户
- 方向 B · 内置 + 自定义合并：内置常量 + 用户自定义双层来源；缺：来源标注/去重/排序交互复杂。不采纳（用户定向）
- 方向 C · 运行时远程目录热更新（非常规）：可运营；缺：远程依赖、攻击面、隐私泄露。不做

### 统一映射模型（用户提出，独立推演后采纳）

- 用户洞察：prefix 本身也是一种映射（改写 = to + from 之后的剩余路径），组合型镜像无法用单一 type 描述
- 数据形态：镜像条目 = 若干映射对（from → to），无 type 概念；改写 = 逐对前缀匹配替换
- prefix 1:1 可表达：to = base + from，改写结果与现有实现逐字节等价——非破坏性（池功能未实现、无存量数据）
- 组合型镜像（混合域名替换与前缀行为）天然可描述；新镜像服务接入从写代码降级为提供映射数据
- 行为边界三分类（用户异议采纳）：命中映射 → 加速；GitHub 已知域（github.com、raw.githubusercontent.com）映射未覆盖 → 原样直连并按 host 聚合提示；非 GitHub 域 → 静默直连
- 代价与缓解：录入繁琐 → 添加时模板预填；jsDelivr 等路径重构型服务映射无法表达（本就不在范围）

### 池管理与验证语义（逐轮收敛）

- 添加完整性：github 与 raw 两条映射必填，按钮合法前禁用；补映射 = 编辑现有条目
- 可达性验证：触发源 = 添加成功事件——入池（不因测试回退）+ 自动首测显示 ✓ 耗时 / ✗ 原因；探测用 GET 小资源，不用 HEAD/OPTIONS（支持参差、405 误报）；格式校验实时本地做
- 重复判定：镜像名即唯一标识，同名即重复；名字填错但映射正确属用户认知负担，插件不加内部复杂性
- 删除：移出池 + 清理该身份全部运行态；删 active 游标回首项
- 空池不可达：最后镜像不可删（开关开 ⇒ 池非空 ⇒ 必在加速；直连 = 关开关；重置 = 恢复初始状态）
- 测试失败：行内标 ✗ + 原因、行内编辑重测、不自动删除（瞬态不丢配置，死镜像由被动引擎记账）

### 单候选与全拉黑的第一性分析

- 插件是可用性的搜寻器而非提供者：全通道失效时路由层无解，是集合属性非设计缺陷
- 自动切换必须保留：目录即偏好、无用户选择模型下它是故障后唯一恢复机制
- 单候选/全拉黑退化 = 原地持续重试：拉黑项继续承担流量、停止记账、30 分钟冷却期满重置（非死锁，最长 30 分钟循环）
- 种子可删（不可删不创造可用性）；解法分布 = 池管理扩充 + 冷却重试 + 状态可见

### 生命周期分层

- 镜像池持久化于 data.json，仅用户池管理操作与播种改变；重启/重载/开关切换均不变（自定义镜像保留）
- 运行态（游标/连败/拉黑/测试结果/未覆盖记录）为会话内存，插件重载或应用重启即清空，池不受影响
- 语义对照：重启 = 只复位运行态；恢复初始状态 = 池重建为种子 + 运行态清空 + 全池首测

### 全池首测触发语义

- 触发 = 池内容建立/重建：首次播种、恢复初始状态；池沿用（开关 off→on、重启、日常）不触发
- 结果喂记账：失败 1 败推进游标、成功稳定——冷启动预定位到首个可用镜像；单轮每镜像至多 1 败、永不触发拉黑
- 佐证边界：开关 off 期间添加镜像，自动首测照常（测试是显式诊断动作）

### 手动切换下一镜像

- 「当前镜像」行加切换按钮，复用自动切换推进语义（跳过拉黑、纯游标移动、不记账）
- 补纯被动盲区：慢而不败的镜像不会触发自动切换，用户可主动跳过
- 与被否决的下拉选择固定镜像不同：轻量临时动作，不引入用户偏好状态；全部拉黑时点击停留原地并提示
