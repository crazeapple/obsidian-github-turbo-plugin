# P-005 调试日志开关

## 背景

- 排查镜像映射配置时需观察「请求原 URL → 改写后 URL」的实际流向，当前引擎无任何日志输出，只能靠猜
- 需求经讨论收敛（2026-09-08，原话见 journal P-005 块）：设置页加调试开关，开启后在 devtool console 输出 `request-url` 流量的改写/直连日志
- 引擎挂载点唯一：`install()` 拦截器是全部 `request-url` 流量的咽喉，原 URL（`extractUrl`）与改写结果（`rewriteUrl` 判定分支）同点可得；`getConfig()` 闭包已贯通设置，加 `config.debug` 布尔短路即可，侵入极小

## 用户故事

- 作为用户，排查镜像映射时，我能在 console 看到每个被加速请求的原 URL 与改写后 URL
- 作为用户，我能用一个设置开关启停日志：默认关闭、重启保持，关闭时零开销
- 作为用户，console 里只有 GitHub 相关流量的日志，不被其他插件请求刷屏

## 范围内

- 设置页「恢复初始状态」区上方新增 Debug 分组，内含调试日志开关：默认关闭，持久化 `accelerator.debug`
- 拦截器内联日志（方案 A，A-008）：
    - 命中映射 → 单行 `[GT] [REWRITE] <origin 去协议> → <rewritten 去协议>`（REWRITE 侧全路径不截断）
    - 未被加速的流量（GitHub 已知域未命中、非 GitHub 域、其他插件流量、探针预改写）→ 一律静默（v1.1：DIRECT 行删除）
- 通道 `console.log`（`console.debug` 默认被 Verbose 过滤隐藏，P-001 教训）；`[GT]` 前缀供 console 文本过滤；去协议口径与设置页详情一致（复用 `displayEndpoint`）
- 关闭时零开销（布尔短路）；探针流量不产生日志（URL 预改写为镜像域、非已知域，自然排除，且结果已在设置页可见）
- 引擎单测新增日志分支用例（伪造 ipc + console 捕获）

## 范围外

- 观测超时 / 回复成败事件的日志（开放问题②，首版仅请求发出时刻；噪音评估后另议）
- 日志级别、导出、设置页内日志查看器（方案 C 已否决）
- DIRECT 日志（v1.1 删除；未来「映射编辑」提案使单映射镜像成为合法输入时可复议）
- 移动端（平台既定不支持）

## 验收标准

AC1：设置页「恢复初始状态」区上方出现调试日志开关，默认关闭，状态持久化（重启 Obsidian 后保持）
AC2：开关开启且加速总开关开启时，命中映射的请求在 console 输出单行 `[GT] [REWRITE] <origin 去协议> → <rewritten 去协议>`，REWRITE 侧全路径
AC3：未被加速的请求（GitHub 已知域未命中、非 GitHub 域、其他插件流量）无任何日志输出
AC4：调试开关关闭时无任何日志输出
AC5：通道为 `console.log`
AC6：探针流量不产生日志
AC7：引擎单测全过（55 基线 + 日志分支新增用例）；构建零错误 + lint 0 error 0 warning

## 边界与异常

- 日志仅在加速总开关开启时工作（拦截器 `config.enabled` 短路在前；调试改写以加速开启为前提）
- 非 `request-url` 通道的流量不在拦截器视野，天然无日志（行为不变）
- 开启日志后高频请求会刷屏，由用户自行开关控制（调试动作的预期形态）
- 正常路径下 GitHub 已知域必被任一镜像覆盖（添加表单强制双映射），未覆盖仅可能源于手工/历史数据——未覆盖告知机制保留，日志不打（v1.1）

## 依赖与关联

- 依赖 P-003 `install()` 拦截器与经由判定（观测记账缺陷修复后的「仅命中 active 映射才改写 + 记账」语义，日志复用同一判定点）
- minAppVersion 1.11.0（P-004 已定版，Debug 分组复用 `SettingGroup`）
- A-008（挂载点与格式的被否备选留痕）
