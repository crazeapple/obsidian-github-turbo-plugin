# P-003 代理镜像池管理与多替换类型

## 背景

- P-002 交付单镜像引擎后，用户提出池管理需求（镜像增加、调整顺序等）——P-002 spec 范围外明确预留的方向
- 键控基础就绪：MirrorCursor 按镜像身份键控，池重排/增删不会张冠李戴
- 统一映射模型（用户提出，独立推演后采纳）：镜像条目 = 映射对列表（from → to），无 type 概念；prefix 镜像 1:1 可表达（to = base + from，与现有实现逐字节等价）；组合型镜像天然可描述；非破坏性（池功能未实现、无存量数据）
- 用户已拍板：纯用户池模型（内置目录降级为首次默认种子）、轻量「测试此镜像」按钮、类型集 = prefix + 域名替换
- 约束：种子集合实现期实测筛选确保全部可用（探索期 4 项仅为候选参考，仅 gh-proxy.com 实测验证可用）；不发布社区插件库

## 用户故事

- 作为用户，我可以向镜像池添加镜像（名字 + github/raw 两条映射），入池后自动获得可达性验证结果
- 作为用户，我可以删除镜像（最后一个不可删），被删镜像不再被使用
- 作为用户，我可以上移/下移镜像，回退顺序随之改变
- 作为用户，我可以在设置页看到当前镜像、镜像池各条目的状态（active/拉黑/候选）与最近测试结果
- 作为用户，我可以对任意镜像点击「测试」验证可达性
- 作为用户，我可以一键「恢复初始状态」回到种子池并重新验证
- 作为用户，当请求未被任何映射覆盖时，我能在设置页看到配置缺口提示

## 范围内

- 纯用户池：TurboSettings.accelerator.pool（有序镜像条目列表）；条目 = 名字（唯一标识，用户填写的镜像 URL）+ github/raw 两条映射对（from → to）
- 播种迁移：无 pool 键时自动播种内置目录；旧 mirrorBase 键继续忽略
- MIRROR_CATALOG 常量降级为 DEFAULT_POOL 播种种子
- 池管理 UI：添加（两条映射必填 + 名字非空且不重复，合法前按钮禁用）、删除（最后一条禁删）、上移/下移、条目展开只读详情（collapsed 条目 = 名字 + 测试结果 + 菜单）
- 可达性验证：添加成功后自动首测一次；行级「测试」按钮重测（GET 改写后的小资源，requestUrl）；结果显示 ✓ 耗时 / ✗ 原因；测试是诊断动作，与加速开关无关
- 失败处理：测试 ✗ 不阻塞入池、不自动删除（行内标 ✗ + 原因）；修复 = 删除后重新添加（映射编辑预留未来提案）
- 游标与记账按镜像名身份运作：删 active 回首项；重置按钮 = 池回种子 + 清运行态 + 全池首测
- 未覆盖告知：GitHub 已知域（github.com、raw.githubusercontent.com）请求未被任何映射覆盖时按 host 聚合，设置页显示提示

## 范围外

- 映射编辑/保存（创建后只读，修改 = 删除重加；预留未来提案）
- jsDelivr 等路径重构型替换方式（映射无法表达，预留未来提案）
- 目录远程热更新、批量主动健康探测（行级手动测试除外）
- 除默认种子外的其他镜像可用性保证（用户自行配置，测试按钮验证）
- 移动端支持、社区插件库发布

## 验收标准

AC1：添加前缀型镜像（名字 + 两条映射）→ 入池、自动首测显示结果、后续请求按该映射改写
AC2：添加域名替换型镜像（github.com 与 raw 域分别映射）→ 改写正确（github.com 路径与 raw 路径分别替换为映射域）
AC3：名字与池内已有条目重复时「添加」禁用并提示
AC4：删除条目 → 移出池、该身份运行态清理、后续请求不再使用；删除 active 时游标回首项
AC5：池仅剩一条时删除动作禁用并提示
AC6：上移/下移后，失败推进的回退顺序跟随新排序
AC7：重载 Obsidian 后池与顺序持久化
AC8：存量数据（无 pool 键）加载后自动播种内置目录且运行正常
AC9：行级测试显示 ✓ 耗时或 ✗ 原因，与镜像实际可达性一致
AC10：GitHub 已知域请求未被任何映射覆盖时，设置页出现未覆盖提示；补全映射后提示消失
AC11：「恢复初始状态」→ 池回种子、运行态清空、自动全池首测
AC12：切换语义回归（P-002：失败推进、3 败拉黑、30 分钟冷却、手动切换均正常）

## 边界与异常

- 名字即身份：修改镜像 = 删除后重新添加（状态重置，语义合理）；名字不参与改写，仅作身份与显示
- 映射均不匹配 → 原样直连并触发未覆盖提示（已知域）；修复路径 = 补全映射或删除条目
- 测试与首测均为诊断动作：失败不阻塞入池、不自动删除；被动引擎对真实流量如实记账（拉黑回退照常）
- 探测/测试与加速开关无关：开关关闭时测试仍可执行（显式诊断）
- 池为空的唯一途径被禁删阻断；引擎无候选优雅直连兜底保留（防御纵深）
