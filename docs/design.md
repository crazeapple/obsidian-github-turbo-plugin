# Design

> 插件的设计文档——各功能域怎么设计、为什么这样设计。
>
> 状态：改写引擎已实现并随 0.1.x 发布；镜像池、可达性测试、调试日志为后续轮（0.2.0 起）设计。

四个域是同一条流水线：镜像池为改写引擎供给映射，可达性测试检验池条目的健康，调试日志观测引擎行为。按数据流向阅读：镜像池 → 改写引擎 → 可达性测试，调试日志横切。

## 镜像池

> 本节为池管理轮（0.2.0）设计；当前版本的池是引擎内置种子池，见「改写引擎 · 种子池」。

### 池模型

纯用户池：条目 = 镜像名（唯一身份）+ 映射对列表；顺序即回退优先级；持久化于插件数据。

### 池操作语义

添加（名字唯一、集中校验）、删除、上移/下移（重排 = 重新声明优先级，活动镜像跟随）的规则与边界。

### 设置页形态

镜像池的展示与操作入口；声明式 Settings API（`SettingDefinitionList`：增删、拖拽排序、空态）与命令式 `display()` 的路线取舍及理由。

### 首项变更语义

目录首项变更（重排/删首项）视为重新声明优先使用对象，活动镜像跟随新首项。

## 改写引擎

### 设计目标

无代理环境下加速内置市场对 GitHub 的访问；对 Obsidian 完全透明——不改界面、不改操作、不改非 GitHub 请求。

### 作用范围

改写面向渲染进程全部指向 github.com 与 raw.githubusercontent.com 的请求——IPC 消息无发送者身份，市场流量与其他插件的 GitHub 流量在通道上不可区分；携带 Authorization 头的鉴权请求豁免改写，恒直连不记账。

### 平台机制

桌面端内置市场的 GitHub 请求经渲染进程 `request-url` IPC 通道过桥（URL 明文），响应按请求 ID 命名频道回达且载荷含 `status`——包装 `ipcRenderer.send` 即可在发出前改写 URL、在回达时观测结果。

### 映射模型

统一映射前缀对 `from → to`：URL 以 `from` 开头则改写为 `to` + 剩余路径；前缀拼接型与域名替换型镜像由同一模型承载，无需分派；映射产物不再二次改写（幂等）。

### 健康记账

失败判定：`/releases/download/` 路径的 404 计失败（上游应有此资源），其余路径 404 视为上游真值不记账；403/429/5xx 与网络层错误计失败；观测超时按失败记账（默认 120 秒，覆盖 release 大文件下载，实现为可注入）。经由语义：只对命中当前镜像映射的流量记账，避免探针/直连流量拖动游标。

### 回退与拉黑

失败后按池顺序推进到下一可用镜像；同一镜像连续失败 3 次本会话拉黑，30 分钟冷却期满自动解除并清零连败；全部镜像拉黑时游标停留原地，请求仍按当前 active 镜像改写发出。会话重置：插件启用时游标回首项，连败与拉黑清零。

### 切换命令

命令面板「GitHub Turbo: Switch to next GitHub mirror」（id `switch-next-mirror`）：手动切到下一个未拉黑候选（循环轮转），Notice 反馈 `Switched to <mirror>`；全部拉黑时提示 `All mirrors are blacklisted`、游标停留原地。它是无设置页阶段的手动杠杆，池管理轮的设置页 Switch 按钮与它共存。

### 种子池

内置种子池开箱即用，名单为实测定稿（2026-11-18，双层判定：HTTP 语义 + Obsidian 内容指纹）：ghproxy.net → cors.isteed.cc → gh-proxy.com，顺序按实测耗时升序。名单随时间漂移，重测工具 `scripts/probe-seeds.mjs` 进仓，漂移时手动重测定稿。

### 平台边界

仅桌面端（依赖 Electron ipcRenderer，结构变化时静默不挂载）；卸载还原原始通道；不收集任何数据。

## 可达性测试

### 双探针

github 域与 raw 域各取一条官方仓库路径作探针；按候选映射分别改写后并发请求——两条映射各自得到验证。

### 双层判定

HTTP 语义层（状态码按失败判定规则）+ 内容指纹层（2xx 但内容非预期则判伪，杜绝停车域误判）。

### 结果语义

测试结果只作诊断展示：失败不阻塞入池、不自动删除；测试属显式诊断，不受拉黑限制。

### 结果展示

逐映射分段的结果呈现（符号 + 耗时/原因）。

## 调试日志

### 开关

设置页独立开关，默认关闭、持久化。

### 格式

改写行：原始地址 → 改写后地址（去协议压缩展示）；直连行与静默边界的取舍。

### 挂载点

日志产生于改写发生处（通道包装内联），不引入额外观测通道。
